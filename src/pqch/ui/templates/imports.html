Federal agencies inventory their cryptography with commercial discovery tools; this workbench uses open-source ones. Neither has to be taken on trust. A tool that exports a CBOM can be run against the mini-agency — eight services with every weakness planted and two decoys per layer — and its CBOM imported here: each entry is placed on a listener, a file in an image or a line of code, its names read the way the workbench reads its own, and the result scored against the answer key. Nothing about the tool is integrated, and nothing is taken from its vendor but its output. No model takes part in placing or scoring. Entries a tool reports with no location the workbench can find again are kept in the import's record by name and not counted.

How: pqch import FILE[=IMAGE] … --tool NAME --key agency/answer-key.yaml. A tool that writes one CBOM per image names the image after =.

"Out of reach": keyed items no scan of this kind can see — a client's certificate, a key exchange only one client offers. A decoy is a planted item that should not be reported as in use — an unserved certificate, a retired key. Flagging one is a false positive the answer key was built to catch. The workbench's row is its latest full scan; an imported tool is scored only on the layers its documents reach.
