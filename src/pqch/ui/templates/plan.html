Moving an estate to post-quantum cryptography is not a list of changes. A certificate authority's root has to move before the certificates it issued; software that cannot take the new algorithms has to be replaced before anything that depends on it; a service is offered the new key exchange before it is required, and only once its clients can follow. None of that is in a list of systems. All of it is in the CBOM — which certificate was issued by which authority, which key sits on which listener, which build a service runs, what each listener accepts — and so the order can be computed, not guessed. That ability to plan the next change, and the one after, from the record is what crypto agility rests on. The plan is computed by rules from scan {{ plan.run }} and the change runs since, every time this page is shown. No model orders it.
