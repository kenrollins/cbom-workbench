cbom-workbench

Crypto agility starts with an inventory you can act on: a cryptography bill of materials, a plan, and changes with proof, on one Dell Pro Max GB10.

Dell Federal × NVIDIA hackathon · November 5, 2026 · build {ver}

Mission outcome. We must know the cryptography that each system uses and which change to make first. Then the agency can meet the post-quantum deadlines. We measure this by the planted weaknesses found and the changes proved on the network.

Summary

The problem. A quantum computer can break the public-key cryptography that agencies use today. Federal direction tells each agency to make a cryptography bill of materials (CBOM). A list of systems does not show the cryptography inside them. A spreadsheet has one row for each system, with no links and no dates. The network and the files contain hundreds of components. The correct order of work depends on the data that each service protects, and for how long.

The solution. The workbench runs on one Dell Pro Max GB10, with no connection to an outside network. Open-source scanners examine a test agency of eight services. Each scanner runs in its own container. The workbench also reads one host fully: its files, its firmware and its management controller. Each finding goes into a signed ledger. The workbench builds the CBOM and the migration plan from this ledger. Rules assess each component and set the order of the steps.

The change. A local NVIDIA Nemotron model writes each configuration edit. The workbench tests the edit on a copy of the service. Then a person approves it, and the runner applies it. Two probes test the live service. A client that offers only the hybrid post-quantum key exchange must connect. A client that offers only classical key exchange must fail. The probes run again after the service restarts.

The trust. A model does not decide a finding or a result. Scanners find, rules assess, probes decide and people approve. A model gets a task only after it passes a written test. The ledger is an append-only file. Each event holds the hash of the previous event, and ML-DSA-65 signatures protect it. No data leaves the box.

How it works

Each step writes to one signed ledger. Rules, scanners and probes decide. A local model only writes and explains. A person approves each change.

Compared with the scanners alone

The test agency has 60 planted weaknesses and an answer key. The workbench uses the same scanners and adds its own file reader and rules. These find the 6 weaknesses that the scanners miss in the image files, without false positives. The 2 network misses are not visible from outside the service.

Scale

The same containers run on two linked GB10s, a Pro Max GB300, a PowerEdge XE server or an AI factory. A larger system serves a larger model and examines more networks at the same time. The ledger and the method do not change. We measured only the single GB10.

cbom-workbench is a personal research project and is open source (kenrollins.github.io/cbom-workbench). It is not a Dell product, reference architecture or supported offering. All numbers come from this GB10 on November 5, 2026, and are in its ledger. Ken Rollins · ken.rollins@federal.dell.com
