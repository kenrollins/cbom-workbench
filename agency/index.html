The test agency. What the workbench is pointed at in this demo: a small, fictional agency built for it, every weakness planted on purpose and written down in an answer key.

A small, fictional federal agency — a benefits portal, a partner API, an inter-agency gateway, a records database and its file drop, a message queue, a case-management application and an administrator's jump host — built in containers on an internal network with no route out. Every cryptographic weakness in it is planted on purpose and written down in an answer key, so what the workbench finds can be scored exactly: what it found, what it missed, and which decoys it was fooled by. Everything on this page is read from the estate's own files — what each service is for, the owner's facts, the listeners and the answer key — not from a scan. It is the estate as built: the state the walkthrough starts from.

Why an answer key

A scan of a real network says what it found; it cannot say what it missed. Here every cryptographic item is written down before any scan runs, so each run is scored against it — found, missed, or fooled.

58 to findPresent and reachable: a key exchange a listener accepts, a certificate it serves, a key file in an image, a weak setting in a configuration file.
9 decoysThings that look like findings and are not: a certificate left in an image that nothing serves, a weak setting in a comment or a file the software never loads. Reporting one is a false positive; a scanner that greps does.
2 out of reachReal, but invisible to any probe from this side: what the file drop offers when it connects out, and which keys partners present. Only passive capture beside them would show it. They stay in the score's denominator and are reported as known misses: the limit of a scan is part of the result.
5 suppliedWhat no scan can discover — the mission each service carries, how long its data must stay secret, whether it is a high-value asset — typed in by the owner. The CBOM carries them labelled supplied, and they never count as coverage. They decide what comes first in the plan.

The roles and clients above are the agency's story; the workbench learns none of it from this page. What it knows comes from the evidence — the wire, the images, the code — and from the owner's facts. Certificates and keys are generated when the images are built, so the key names them by path and algorithm, never by fingerprint. The full list: agency/answer-key.yaml.
