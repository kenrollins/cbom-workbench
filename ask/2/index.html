Ask the CBOM. A question in plain words, answered from the inventory's own components and the ledger events behind them. The model sees only the passages retrieved for the question; every event it cites is checked against the ledger by a rule, and the verdict is shown beside it.

The CBOM is a document a person can read, and a model can read it too. Here the question is embedded, the eight components nearest to it are handed to the model as passages with their evidence event ids, and the typed reply names the components it rests on and the events it cites. The model never decides whether it cited well: a rule checks each event id against the ledger and against what the model was shown. An id that fails is marked, not hidden. Retrieval and the answer are measured apart (eval/ask), with a floor written before the first run.

1 · Embedthe question becomes a vector (lab/embed)
2 · Retrievethe eight nearest CBOM entries, and the chain above each, by rule
3 · Answerlab/reason on the deliberate tier, from those passages only
4 · Checkevery cited event against the ledger: a rule, not a model
