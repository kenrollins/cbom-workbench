The plan. What the CBOM says depends on what, what comes first, and in what order — the migration plan an inventory of systems cannot give, computed from the mini-agency's CBOM.

Moving an estate to post-quantum cryptography is not a list of changes. A certificate authority's root has to move before the certificates it issued; software that cannot take the new algorithms has to be replaced before anything that depends on it; a service is offered the new key exchange before it is required, and only once its clients can follow. None of that is in a list of systems. All of it is in the CBOM — which certificate was issued by which authority, which key sits on which listener, which build a service runs, what each listener accepts — and so the order can be computed, not guessed. That ability to plan the next change, and the one after, from the record is what crypto agility rests on. The plan is computed by rules from scan 01M5JFEP7D145D2T38TW0S6631 and the change runs since, every time this page is shown. No model orders it.

3 What comes first, and why

The order of the lanes above. OMB M-26-15 prioritizes a high-impact system, a High Value Asset, or data still sensitive in 2030; among those, the longer the data must stay secret, the sooner its key exchange matters — traffic recorded today is decrypted when the key exchange falls. The owner's facts are supplied; the rest is the CBOM's.

4 Carrying out a step

Each step links to where it is resolved: a change proposed, rehearsed on a copy, checked against every kind of client, approved by a person and proved on the wire — the resolution stage — or, where no setting can move it, a change package for the replacement. When a change lands, its step turns done here.
