    Lessons¶

    Standing guidance: the rule, why it holds, when it applies.

    1. 01 When verifying that a post-quantum key exchange is required, offer every classical group, not the ones the server was configured with — A refuse-probe built from the server's old configuration proves only that the old configuration is gone; build it from the whole class being retired, and let an enumerating scan overrule it.
    2. 02 Give an isolated Docker network no host address, and test for it — An internal Docker bridge has no route out, but the host still sits on it as the gateway; set the gateway mode to isolated, and probe for the host as well as for a route.
    3. 03 Carry a registry in an offline bundle; docker save and docker load do not preserve digest references — An image saved by digest loads back as an untagged id, and an image saved by tag loads back under a new digest; an air-gapped bundle that pins by digest needs a local registry, filled registry-to-registry with every platform.
    4. 04 Believe an identity header only on a connection from the proxy that sets it — A forward-auth proxy strips and sets the user header, but an upstream that listens where anything else can reach it will accept the same header typed by hand.
    5. 05 Score an inventory for what it invents, and put a decoy in every layer it is scored on — A coverage score with no penalty for unplanted claims is maximized by claiming everything; count claims the answer key does not hold as false positives, and never show an untested decoy as avoided.
    6. 06 Record which container a scan reached, and join evidence only when it is the one you think it is — An address is not an identity: before linking what was seen on the wire to what was found in an image, check that the container at that address runs that image, at the start and the end of the scan.
    7. 07 Take the key that verifies a signed log from somewhere other than the log — A public key stored beside the data it verifies can be replaced along with it; record the key's id and the latest signed checkpoint somewhere the writer cannot reach.
    8. 08 Identify a key in an inventory by the hash of its public key, not by where it was found — "An RSA certificate at this address" cannot tell a renewed certificate from the old one, and an image digest in the location makes every rebuild look like a new estate; put the public key's hash in the identity and keep build identifiers out of it.
    9. 09 Time a file scanner on the bare base image first; symlinks, not size, can set its cost — cbomkit-theia's secrets plugin reads a file's contents once for every symlink that points to it, so a BusyBox-based image costs it about 94 s whatever its size; measure the base before blaming the image.
    10. 10 Count a key-exchange group as accepted only when it is the one negotiated — and sweep TLS 1.2 groups as TLS 1.2 — A handshake can succeed on a group the client did not offer, and fail after the server has accepted the one it did; judge each probe by the group the server chose.
    11. 12 Check cited evidence against the question it was meant to answer, then derive the conclusion again — That a cited test really ran proves nothing unless it is the test the claim calls for, run after the change, against the thing changed — and the conclusion follows from its raw output.
    12. 13 To bound when a logged event happened, sign the log just before it and just after — A timestamped signature over an event shows it existed by then; only an earlier signature that the event is chained after shows it did not exist before.
    13. 15 Hash every blob in an offline bundle's registry before serving it, and keep the checksum file's own hash somewhere else — A registry serves what is on disk without checking it, a client does not re-fetch what it holds, and a checksum file edited together with what it lists still passes.
    14. 16 Count a change as applied only when the service answers, and put the old configuration back when it does not — The orchestrator reporting a container started is not the service coming up; a configuration the service cannot load leaves it down unless the applier restores the previous one.
    15. 17 In a bundle build, always rebuild what must match the source and record the commit; reuse only what must not change — A build step that skips an image because its tag already exists ships whatever was built first; a test of the bundle then tests old code.
    16. 18 Observe what a service accepts with nothing configured before planning its migration — The same TLS library gives different key-exchange defaults under different servers; with no line set, one already offers the hybrid group and another does not, and both accept RSA key transport.
    17. 19 Label a cause only after changing it and watching the effect go — A reference answer of the form 'this line causes that behaviour' is earned by two observations: the behaviour with the line as written, and its absence with the line changed.
    18. 20 Before reading a configuration, know which occurrence of a setting wins in that software — OpenSSH takes the first value it reads, PostgreSQL the last, nginx the innermost block; the same two lines in a different order, or an include in a different place, give a different listener.
    19. 21 Set a floor per role before comparing two models, and repeat every call before believing it — A model that beats the smaller one is not thereby good enough: each role needs an absolute bar set by what depends on its output, and a reply at temperature 0 is one draw, not an answer.
    20. 24 A hardware label in a config is a claim; record what served the call — When model calls go through a gateway that can move a lane between machines, the hardware label in the caller's config is a claim that goes stale silently; record the upstream the gateway names on each reply beside the label, and check the label against it before publishing a timing.
    21. 25 Size the scanner network's address range to the parallelism, and record a job that never started as its own failure — When scanners run as containers on a network with a fixed address range, the range bounds how many can run at once; a job that fails because no address was free must be recorded as a runner failure with its reason, never as a scan the target did not answer.
    22. 26 Name the reasoning setting beside the model in every measurement and binding — A hybrid-reasoning model's result depends on its reasoning switch and effort level as much as on its weights, so a measurement, a table row or a tier binding that names the model without its reasoning setting is incomplete, and a gateway lane that pins the setting is part of the model's name.
    23. 27 Before keying a TLS listener, probe each kind of key exchange on its own: named groups, finite-field DHE, RSA key transport — A TLS 1.2 listener can establish keys three ways — a named group, an ephemeral finite-field group it supplies itself, or encryption to its RSA key — and a probe that offers one kind says nothing about the other two; key a listener only after a probe per kind, or a full cipher-suite enumeration.
    24. 28 Read a certificate's CA flag together with its key usage; a self-signed server certificate is usually marked CA:TRUE — openssl req -x509 writes basicConstraints CA:TRUE into every self-signed certificate it makes, server certificates included, so an inventory rule that treats CA:TRUE as 'a certificate authority' misfiles them; a certificate authority's certificate is one with CA:TRUE and keyUsage keyCertSign, and the in-use rules for leaf certificates must not be applied to it.
    25. 29 Give a listener that carries TLS behind a protocol upgrade its own scan profile; a plain TLS scan of its port is silent, not negative — PostgreSQL, SMTP, IMAP, LDAP and others start TLS only after an in-protocol request, so a scanner that opens the port and speaks TLS gets nothing back and reports nothing; the listener's protocol must be named in the scope and bound to a profile that speaks the upgrade, and a scope protocol no profile claims must be visible as unscanned, never as clean.
    26. 31 Confirm every cause an answer key names by changing it, including the ones written as annotations — A cause written into an answer key as an aside — a trace, a hint, a why — is a label like any other and needs the same two observations; one the key's author wrote from reading named a commented-out line as the cause of a default, and the first model trace to reach it was right where the key was wrong.
    27. 32 Ask the protocol stack's runtime what it will negotiate before calling a migration blocked, or not blocked, by its supplier — Whether software can offer a post-quantum algorithm is a property of the protocol stack that negotiates it, not of the cryptographic library underneath; ask that runtime for its own list, with no network, and keep the raw answer.
    28. 33 Read a validated module's certificate for the algorithm you need, and check that the module is active, before calling a system validated — A FIPS 140 validation covers the algorithms its certificate lists, in the module it names, when that module is the one in use; the library's name and version say none of that, and a FIPS provider shipped in an image is not one in use.
    29. 34 Score the retrieval step on its own before scoring a model's answer over it — When a model answers from retrieved passages, record what was retrieved with every answer and score whether the passage that settles the question was among it; a faithful model fails every item retrieval misses, and the failure is not the model's.
    30. 35 Compare two inventories by the identity of each observation and by what it says, leaving out references to the records behind it — A component's reference should be a hash of what was observed, so the same thing seen twice is the same entry; and a comparison should strip the event ids an entry cites, which are new on every scan, or every scan of an unchanged estate looks like change.
    31. 36 When verifying that a listener requires post-quantum key establishment, probe TLS 1.2 on its own; a classical-only TLS 1.3 client is refused, not downgraded — A server that shares no group with a TLS 1.3 client refuses it rather than falling back to TLS 1.2, so a negative probe offering every classical group says nothing about TLS 1.2; a listener restricted to the hybrid group can pass it while still accepting finite-field Diffie-Hellman and RSA key transport over TLS 1.2.
    32. 37 When a probe claims a handshake the enumerating witness does not find, call the verdict inconclusive and say why; neither side settles it — A verifier that lets its witness only lower a verdict will silently turn a misread probe into a false 'not enforced'; when the negative probe reports a key exchange the witness says the listener does not offer, one of the two misread the listener, and the verdict is inconclusive with the reason, until a person reads the raw output.
    33. 38 Before citing or redrawing a standard, read its status on the publisher's page; cite the current revision by its own identifier — A withdrawn publication keeps circulating — in search results, in summaries, in copies saved earlier — so the identifier in hand may not be the one in force; read the status, cite the superseding revision, and say whether the part relied on changed.
    34. 39 Every label in a diagram of what a system does is a claim; fill it from the record and check each against the record before it is shown — A box that says 'signed', 'by rule' or 'reached' reads as fact, and a framework's boxes invite filling them with what the system ought to do; compute each label from the ledger where it can be computed, and check the rest line by line against the ledger before the page is published.
    35. 41 Before approving a change that requires post-quantum key establishment, probe each kind of client against a copy with the change; enforced says it landed, not whom it refuses — A require change verified enforced has, by definition, refused every client that cannot offer the hybrid group; measure which kinds those are, against the live listener and a copy with the proposed configuration, and put that table in front of the approver.
    36. 43 Report a change's time from approval to proof beside its time from policy to proof; the gap is the wait for a person, not the system — Time from the policy decision to the last verdict includes however long the change waited for an approver; shown alone it reads as the system's speed, so headline the approval-to-proof time and give the other as what it is.
    37. 48 Write each CBOM fact in CycloneDX's own field; where the standard has none, name the property as the tools you feed read it — Two valid CycloneDX 1.6 CBOMs of the same estate can share almost nothing a policy engine reads: the standard leaves the TLS key-exchange group and every SSH algorithm without a field, so each tool invents property names, and a tool that also skips the fields the standard does define is judged on nothing.
    38. 49 Before binding a role to an inference engine on a new machine, check four things the engine decides for itself: that it has a profile for the GPU, the context window it will serve, the share of memory it will take, and the model id it answers to — An engine container chooses its GPU profile, its context window, its memory share and its served model id on its own; on a desk-side box with unified memory each of the four can silently make a role unservable, and only a call through the seam with the role's real request shows it.
    39. 50 When a bundle keeps an image from one build to the next, key it to a hash of its build context, never to its name — A bundle that reuses an image by name will carry a stale service for as long as the name stays the same; the kept image must be keyed to what it was built from, and the test that catches it is scoring the bundle-started estate against the answer key.
    40. 51 Where a protocol upgrade can be refused, ask for it once and record the answer before scanning what it would carry: a scanner that cannot represent a refusal records a timeout — A TLS scanner pointed at a PostgreSQL listener that refuses TLS waits out its budget and records a timeout, which reads as a failed scan; one SSLRequest answered N in a millisecond is the finding: the database speaks in the clear.
    41. 52 An inventory read as an ordinary user must list every path it could not open, and the plan must carry the privileged read as a step — Reading a server's files without privileges sees the public half of each key pair and none of the private keys; an inventory that drops the unreadable files silently looks complete and is not, so the reader lists them and the plan asks for one privileged, read-only pass.
    42. 53 An offline install carries the build backend with the wheelhouse and installs outside the lock file; nothing in the runbook calls the package manager's run command — A wheelhouse of runtime wheels is not enough: the project's own build needs its backend, a locked sync fetches from the lock's recorded URLs even with every wheel on disk, and a loader that shells out to uv run re-resolves the project on every call; install with uv pip --offline --no-index and run tooling under the environment's own interpreter.
    43. 55 A reply cap on a thinking tier is a thinking budget: set it from the measured tokens of the role's hardest items, and record a cut-off as an empty reply — When a role is bound to an engine with reasoning on, the reasoning counts against the reply's token cap; a cap sized for the answer alone returns nothing on the items that need the most thought, and the only safe reading of a cut-off is a wrong reply.
    44. 56 A signer's first signature over an event is a floor on the span that starts there, never a reading of it; check a ledger's clock against the bracket, not the floor — An independent signer says when an event existed by (the first signature over it) and when it cannot have existed before (the last signature before it); a span measured from the first-seen time is a lower bound, and a ledger whose own span falls inside that bracket agrees with the signer.
    45. 58 A model whose chat template thinks by default must be told not to on every plain call, and its reply's shape belongs in the prompt and a validator, not in the engine's grammar — Nemotron's chat template reasons unless the request turns it off, so a short plain call spends its whole budget thinking and returns nothing; turn thinking off in the tier's request block, and with thinking off describe the JSON shape in the prompt and validate it, because the engine's structured-output grammar can run a call to its cap.
    46. 60 Before a component goes in an architecture picture, find the line of code that calls it; a stack drawn from what the box has installed claims parts the system never uses — An architecture drawing is a claim about what the system does, so each box in it needs a call site, and each path through it needs a code path; drawing what is installed beside the system, or what a reference design would use, puts parts in front of an audience that a single question exposes.
    47. 63 A static copy of a page whose answer comes from a model shows a call made once and labelled, offers only the questions recorded, and runs the rule's check again where it is built — A published, static copy of the workbench has no model to call; its Ask the CBOM page shows the example questions answered once by a real call, labelled with the model, the hardware and the date, and recomputes every citation's verdict against the ledger it is published with, so the verdict a reader sees is never a stored one.
    48. 64 Run the accessibility check in every colour scheme a page ships; a palette that passes in light can fail in dark, and the reverse — WCAG contrast is computed from the colours a reader is shown, so a page with a dark and a light scheme is two pages to the checker; run it once per scheme.
    49. 66 Pinning a self-signed certificate by making it the only trust anchor still checks its dates; an expired management-controller certificate fails the pin — Loading the certificate a server served as the context's only trust anchor (with partial-chain verification for a leaf a CA issued) is a sound pin in Python's ssl module and anything built on OpenSSL, but OpenSSL still checks the anchor's validity dates, so a long-expired self-signed controller certificate is refused; renew it before turning the pin on, or the read stops before it starts.
    50. 67 Publish a running system as a recording, a record and notes; never as a static copy of its pages with the buttons disabled — A static copy of a live application's pages costs a fixture, a template branch and a dead-button note per page and grows with the application's features, not with its story; publish a recording, the documents it produced with their hashes, and screenshots in the notes instead.
    51. 68 When two sources describe one asset, keep every claim, put one in force by the grade of its evidence, and show the rest as dissent; never fold two values into a list — An inventory built from several tools gets two values for one field sooner or later; folding them into a list of both changes the field's type and tells the reader nothing, and taking the first silently loses the other. Keep each as a claim with its grade (watched on the wire, read from a host, parsed from a file, reported in a document), project the best-graded one, write the disagreement beside it, and let only a person's recorded resolution override the rule.
    52. 69 A policy pack written from secondary summaries is marked unverified and applies no date; the primary is read, hashed and quote-checked before any of its dates or names counts — Summaries of a standard describe the version their authors read; the standard moves on. A pack built from them carries verified: false, sets no deadline and marks every status provisional until the primary document is read first-hand, its hash recorded and every quote in the pack checked against its text by the loader; the CNSA 2.0 pack's five-category timeline, taken from two summaries that agreed, was not in the FAQ's current version at all.
    53. 70 A number shown on two pages is computed in one place; a page that counts a rule's events and a page that counts the document's entries will disagree — A rule judges each observation and the document folds several observations onto one entry, so a count of the rule's events and a count of the document's entries are two different numbers under one label; every page that shows the figure reads it from the same projection, and a test holds the two readers equal.
    54. 71 An automated keyboard pass counts only the controls that are shown; a control inside a closed disclosure is reached through its summary, and a page that takes focus on load is walked from where it starts — A Tab-order check that compares the controls it reached with every focusable element in the page reports traps that do not exist: links inside a closed details element are not in the tab order until it is opened, and a page that focuses its input on load starts part-way down. Count what is shown, follow the wrap-around, and explain every difference before reporting one.
    55. 73 A demonstration written around one machine goes stale the day the machine leaves; name hardware once, as where a run was recorded, and build the beats on the approach — A stage whose beats name a box, its chips and its model on every screen is true for one day and one machine. Four days later its recording came from a different host with different models, and three machines were named across eight beats with no reconciliation. The fix is structural: the beats describe the approach, and hardware appears once, as the provenance label on the run the copy shows.
    56. 75 Score a copy of an estate through an address map on the copy's scope, never through an edited key; judge a remediated item by when the copy was taken — When two tools must inventory the same machines, the estate is copied to a network both can see and re-addressed; the copy's scope names each listener's original, the scorer maps addresses back at matching time, the one key stays the source of truth, and the copy's CBOM keeps the addresses a sensor there sees. A change the estate applied counts as remediated in the copy only if it was verified before the copy was taken.
    57. 76 Read another tool's document in its own shape before scoring it; a reader's blind spot is otherwise recorded as the tool's score — A CBOM arrives as components-as-assets placed by host:port or as components-as-listeners with the facts in properties and the place as src=; an importer that reads one shape scores the other at zero, and the zero is its own. The reader chooses per component, counts what it sets aside by reason, and is held by a round trip of its own writer's document.
    58. 78 A positive verdict needs positive evidence; "nothing was attributed" is its own state — A rule that answers "met" when its list of problems is empty answers "met" for everything it never looked at; a migration item with no finding attributed to its service is not-assessed, and a listener on which no key exchange was observed is unobserved, neither compliant nor classical.
    59. 79 A scan that did not connect is not a scan that found nothing; the tool's own statement decides, not the container's exit — An unreachable listener recorded as a completed scan with zero findings is counted as reached and clean; whether a scan happened is read from what the tool wrote, because one scanner's exit code is its policy verdict and another's is a count, and a scan that fails part-way still closes its window and its run on the ledger.
    60. 80 A check that had nothing to check must say so, and the tool that publishes must refuse without its rules — A leak check whose pattern file is absent matches nothing and prints the sentence a clean result prints; the check reports how many patterns it held, the one tool that pushes refuses to start without them, and a mark is stripped in one exact form while anything that resembles a mark is refused.
    61. 81 Text checks do not read pixels: scrub a page before the browser draws it, check what it shows, and choose what is published by the scope it was authorized under, not by its kind — A screenshot carries whatever the page showed, and no pattern over text files reads it; the capture tool rewrites the page's HTML before it is drawn and stops on a leak match in the text shown, fixtures use invented addresses, and a run is public by the scope it ran under, never by its kind.
    62. 82 Delete a shared artefact by who still cites it, and record the intent before the act — Retention that deletes what an expired run cites deletes evidence a younger run cites too; a file goes only when no run outside the pass cites it, a path is resolved and must lie inside the store, the key a kept ledger verifies with stays, and the intent goes on the ledger before the first unlink.
    63. 83 A writer enforces what its verifier requires — A verifier that refuses a backward timestamp or a fused line, over a writer that checks neither, turns one clock step or one lost newline into a ledger that can never verify again; every condition verify() refuses is a condition append() prevents, under the same lock.
    64. 84 A test double must apply the one transformation the real boundary applies — A fake ssh that executes its argument list is kinder than sshd, which joins the words and hands them to a shell; a route tested against the fake failed on a real server and would have run a scoped path's $() on it. The stand-in now does what the boundary does, and nothing of the scope travels on the remote command line.
    65. 85 Two absences are not a match, and "restored" describes what is running — A verdict bound to no container passed its binding check because nothing equals nothing, and a failed apply wrote the old file back and said restored while the new configuration could still be serving; presence is required before comparison, and after any failed recreate the service is recreated on the restored file and the record says what listens.
    66. 86 Excuse a miss only on evidence, and take what is excused out of the count — A keyed item a change removed is not a miss, but only when the listener's latest landed change is the one that removed it, the item is not the group that change requires, a copy is declared to carry the change, and the column looked at that listener; and an item set aside leaves the denominator as well as the numerator, so the page cannot print 35/40 beside "out of the denominator".
    67. 87 A majority is counted on the one decision; an optional model step degrades, it does not raise — Three replies grouped by every field they carry let two that agree on the decision lose to one that does not; the vote is counted on the single question, more than half of the calls made must agree, the descriptive fields are the commonest among those who agreed, and a model call that fails leaves the candidate "not read" with the counts and the scan whole.
    68. 88 A demonstration steps on the presenter's key; a replay on a timer makes the presenter wait for the screen, or talk past it — A stage that replays a recorded change at its own speed, or brings its bands and journeys in on timers, puts the screen in charge of the talk. Every beat with more than one thing to show is a list of steps: next shows the next, back takes the last away, the heading says which step of how many, and the beat is left only after its last step.
    69. 89 Before measuring a model on a job, read the facts the job hands it; a wrong fact comes back as a fluent, wrong sentence and is scored against the model — The role that speaks one line per plan row was handed a listener's posture as its key-exchange state and a step that had already landed as its next step. The model repeated both faithfully. The first measurement would have failed the model for the input's errors; with the facts corrected, 24 of 24 lines passed the rule check and a person's read.
