    Lessons¶

    Standing guidance: the rule, why it holds, when it applies.

    1. 01 When verifying that a post-quantum key exchange is required, offer every classical group, not the ones the server was configured with — A refuse-probe built from the server's old configuration proves only that the old configuration is gone; build it from the whole class being retired, and let an enumerating scan overrule it.
    2. 02 Give an isolated Docker network no host address, and test for it — An internal Docker bridge has no route out, but the host still sits on it as the gateway; set the gateway mode to isolated, and probe for the host as well as for a route.
    3. 03 Carry a registry in an offline bundle; docker save and docker load do not preserve digest references — An image saved by digest loads back as an untagged id, and an image saved by tag loads back under a new digest; an air-gapped bundle that pins by digest needs a local registry, filled registry-to-registry with every platform.
    4. 04 Believe an identity header only on a connection from the proxy that sets it — A forward-auth proxy strips and sets the user header, but an upstream that listens where anything else can reach it will accept the same header typed by hand.
    5. 05 Score an inventory for what it invents, and put a decoy in every layer it is scored on — A coverage score with no penalty for unplanted claims is maximized by claiming everything; count claims the answer key does not hold as false positives, and never show an untested decoy as avoided.
    6. 06 Record which container a scan reached, and join evidence only when it is the one you think it is — An address is not an identity: before linking what was seen on the wire to what was found in an image, check that the container at that address runs that image, at the start and the end of the scan.
    7. 07 Take the key that verifies a signed log from somewhere other than the log — A public key stored beside the data it verifies can be replaced along with it; record the key's id and the latest signed checkpoint somewhere the writer cannot reach.
    8. 08 Identify a key in an inventory by the hash of its public key, not by where it was found — "An RSA certificate at this address" cannot tell a renewed certificate from the old one, and an image digest in the location makes every rebuild look like a new estate; put the public key's hash in the identity and keep build identifiers out of it.
    9. 09 Time a file scanner on the bare base image first; symlinks, not size, can set its cost — cbomkit-theia's secrets plugin reads a file's contents once for every symlink that points to it, so a BusyBox-based image costs it about 94 s whatever its size; measure the base before blaming the image.
    10. 10 Count a key-exchange group as accepted only when it is the one negotiated — and sweep TLS 1.2 groups as TLS 1.2 — A handshake can succeed on a group the client did not offer, and fail after the server has accepted the one it did; judge each probe by the group the server chose.
    11. 11 Prove a passive-monitoring script fires on traffic you generated before reading its silence as absence — Zeek ran a handler for an event that does not exist without a word and logged nothing; run every new detection against traffic known to contain the thing it detects.
    12. 12 Check cited evidence against the question it was meant to answer, then derive the conclusion again — That a cited test really ran proves nothing unless it is the test the claim calls for, run after the change, against the thing changed — and the conclusion follows from its raw output.
    13. 13 To bound when a logged event happened, sign the log just before it and just after — A timestamped signature over an event shows it existed by then; only an earlier signature that the event is chained after shows it did not exist before.
    14. 14 Do not switch branches under a running container that bind-mounts the tree; make the health check read the files — A bind mount follows the directory that existed when the container started; when a checkout deletes and recreates that directory, the container keeps an empty one and a liveness check still passes.
    15. 15 Hash every blob in an offline bundle's registry before serving it, and keep the checksum file's own hash somewhere else — A registry serves what is on disk without checking it, a client does not re-fetch what it holds, and a checksum file edited together with what it lists still passes.
    16. 16 Count a change as applied only when the service answers, and put the old configuration back when it does not — The orchestrator reporting a container started is not the service coming up; a configuration the service cannot load leaves it down unless the applier restores the previous one.
    17. 17 In a bundle build, always rebuild what must match the source and record the commit; reuse only what must not change — A build step that skips an image because its tag already exists ships whatever was built first; a test of the bundle then tests old code.
    18. 18 Observe what a service accepts with nothing configured before planning its migration — The same TLS library gives different key-exchange defaults under different servers; with no line set, one already offers the hybrid group and another does not, and both accept RSA key transport.
    19. 19 Label a cause only after changing it and watching the effect go — A reference answer of the form 'this line causes that behaviour' is earned by two observations: the behaviour with the line as written, and its absence with the line changed.
    20. 20 Before reading a configuration, know which occurrence of a setting wins in that software — OpenSSH takes the first value it reads, PostgreSQL the last, nginx the innermost block; the same two lines in a different order, or an include in a different place, give a different listener.
    21. 21 Set a floor per role before comparing two models, and repeat every call before believing it — A model that beats the smaller one is not thereby good enough: each role needs an absolute bar set by what depends on its output, and a reply at temperature 0 is one draw, not an answer.
    22. 22 Deploy from a checkout nobody edits — A running container that bind-mounts a directory from a development tree breaks silently when a branch switch replaces that directory; run a deployment from its own detached checkout, with its state beside it, and move it to a commit on purpose.
    23. 24 A hardware label in a config is a claim; record what served the call — When model calls go through a gateway that can move a lane between machines, the hardware label in the caller's config is a claim that goes stale silently; record the upstream the gateway names on each reply beside the label, and check the label against it before publishing a timing.
    24. 25 Size the scanner network's address range to the parallelism, and record a job that never started as its own failure — When scanners run as containers on a network with a fixed address range, the range bounds how many can run at once; a job that fails because no address was free must be recorded as a runner failure with its reason, never as a scan the target did not answer.
    25. 26 Name the reasoning setting beside the model in every measurement and binding — A hybrid-reasoning model's result depends on its reasoning switch and effort level as much as on its weights, so a measurement, a table row or a tier binding that names the model without its reasoning setting is incomplete, and a gateway lane that pins the setting is part of the model's name.
    26. 27 Before keying a TLS listener, probe each kind of key exchange on its own: named groups, finite-field DHE, RSA key transport — A TLS 1.2 listener can establish keys three ways — a named group, an ephemeral finite-field group it supplies itself, or encryption to its RSA key — and a probe that offers one kind says nothing about the other two; key a listener only after a probe per kind, or a full cipher-suite enumeration.
    27. 28 Read a certificate's CA flag together with its key usage; a self-signed server certificate is usually marked CA:TRUE — openssl req -x509 writes basicConstraints CA:TRUE into every self-signed certificate it makes, server certificates included, so an inventory rule that treats CA:TRUE as 'a certificate authority' misfiles them; a certificate authority's certificate is one with CA:TRUE and keyUsage keyCertSign, and the in-use rules for leaf certificates must not be applied to it.
    28. 29 Give a listener that carries TLS behind a protocol upgrade its own scan profile; a plain TLS scan of its port is silent, not negative — PostgreSQL, SMTP, IMAP, LDAP and others start TLS only after an in-protocol request, so a scanner that opens the port and speaks TLS gets nothing back and reports nothing; the listener's protocol must be named in the scope and bound to a profile that speaks the upgrade, and a scope protocol no profile claims must be visible as unscanned, never as clean.
    29. 31 Confirm every cause an answer key names by changing it, including the ones written as annotations — A cause written into an answer key as an aside — a trace, a hint, a why — is a label like any other and needs the same two observations; one the key's author wrote from reading named a commented-out line as the cause of a default, and the first model trace to reach it was right where the key was wrong.
    30. 32 Ask the protocol stack's runtime what it will negotiate before calling a migration blocked, or not blocked, by its supplier — Whether software can offer a post-quantum algorithm is a property of the protocol stack that negotiates it, not of the cryptographic library underneath; ask that runtime for its own list, with no network, and keep the raw answer.
    31. 33 Read a validated module's certificate for the algorithm you need, and check that the module is active, before calling a system validated — A FIPS 140 validation covers the algorithms its certificate lists, in the module it names, when that module is the one in use; the library's name and version say none of that, and a FIPS provider shipped in an image is not one in use.
    32. 34 Score the retrieval step on its own before scoring a model's answer over it — When a model answers from retrieved passages, record what was retrieved with every answer and score whether the passage that settles the question was among it; a faithful model fails every item retrieval misses, and the failure is not the model's.
    33. 35 Compare two inventories by the identity of each observation and by what it says, leaving out references to the records behind it — A component's reference should be a hash of what was observed, so the same thing seen twice is the same entry; and a comparison should strip the event ids an entry cites, which are new on every scan, or every scan of an unchanged estate looks like change.
    34. 36 When verifying that a listener requires post-quantum key establishment, probe TLS 1.2 on its own; a classical-only TLS 1.3 client is refused, not downgraded — A server that shares no group with a TLS 1.3 client refuses it rather than falling back to TLS 1.2, so a negative probe offering every classical group says nothing about TLS 1.2; a listener restricted to the hybrid group can pass it while still accepting finite-field Diffie-Hellman and RSA key transport over TLS 1.2.
    35. 37 When a probe claims a handshake the enumerating witness does not find, call the verdict inconclusive and say why; neither side settles it — A verifier that lets its witness only lower a verdict will silently turn a misread probe into a false 'not enforced'; when the negative probe reports a key exchange the witness says the listener does not offer, one of the two misread the listener, and the verdict is inconclusive with the reason, until a person reads the raw output.
    36. 38 Before citing or redrawing a standard, read its status on the publisher's page; cite the current revision by its own identifier — A withdrawn publication keeps circulating — in search results, in summaries, in copies saved earlier — so the identifier in hand may not be the one in force; read the status, cite the superseding revision, and say whether the part relied on changed.
    37. 39 Every label in a diagram of what a system does is a claim; fill it from the record and check each against the record before it is shown — A box that says 'signed', 'by rule' or 'reached' reads as fact, and a framework's boxes invite filling them with what the system ought to do; compute each label from the ledger where it can be computed, and check the rest line by line against the ledger before the page is published.
    38. 40 Draw a cryptographic inventory in columns along its dependency chain, not as a force-directed graph — A CBOM already has an order — service, listener or image, asset, file — so draw each link of that chain as a column, one service's chain at a time, and group bulk files by directory; a force layout throws that order away and, unbounded, drifts nodes off the canvas.
    39. 41 Before approving a change that requires post-quantum key establishment, probe each kind of client against a copy with the change; enforced says it landed, not whom it refuses — A require change verified enforced has, by definition, refused every client that cannot offer the hybrid group; measure which kinds those are, against the live listener and a copy with the proposed configuration, and put that table in front of the approver.
    40. 42 Before trusting a discovery tool's silence, show it something it should find; an empty result is a finding about the tool until then — A scanner that reports nothing has either found nothing or cannot see — a hybrid group its TLS library lacks, a library it has no rules for, code it cannot resolve without a build — and only a known positive tells the two apart.
    41. 43 Report a change's time from approval to proof beside its time from policy to proof; the gap is the wait for a person, not the system — Time from the policy decision to the last verdict includes however long the change waited for an approver; shown alone it reads as the system's speed, so headline the approval-to-proof time and give the other as what it is.
    42. 44 Publish a curated export, checked for leaks, not the working repository; and keep the list of what must not leak out of the published tools — A working repository built in a real environment carries that environment in its history, its tests and its notes; publish a fresh tree exported from it, with private passages marked at the source and stripped on export, a scan that refuses the export on any match, and the scan's own patterns kept private.
    43. 45 Score an inventory against a key that knows about changes: an item a verified change removed is remediated, not missed — When the estate an answer key describes can be changed, a scan after a verified change no longer sees what the change removed; count each such item as remediated, by the change event that removed it, and take it out of the denominator, or every successful migration reads as a drop in coverage.
    44. 46 After publishing a repository, read its own checks: they run in an environment the export was never tested in — A repository published from a private working copy carries workflow files written for some earlier state of it; they run on every public push, and a red mark on the front page is the first thing a reader sees. Run the workflows' steps on a clean copy of the export before publishing, and read their result after.
    45. 47 Before a demonstration, open the published page in a browser at each width it will be seen at, and read its network log — A test suite, a link crawl and a leak check all pass on a page whose fonts never load and whose figure collapses on a phone; only a browser, rendering the published copy at desktop and phone width with the network log open, shows what a visitor sees.
    46. 48 Write each CBOM fact in CycloneDX's own field; where the standard has none, name the property as the tools you feed read it — Two valid CycloneDX 1.6 CBOMs of the same estate can share almost nothing a policy engine reads: the standard leaves the TLS key-exchange group and every SSH algorithm without a field, so each tool invents property names, and a tool that also skips the fields the standard does define is judged on nothing.
    47. 49 Before binding a role to an inference engine on a new machine, check four things the engine decides for itself: that it has a profile for the GPU, the context window it will serve, the share of memory it will take, and the model id it answers to — An engine container chooses its GPU profile, its context window, its memory share and its served model id on its own; on a desk-side box with unified memory each of the four can silently make a role unservable, and only a call through the seam with the role's real request shows it.
    48. 50 When a bundle keeps an image from one build to the next, key it to a hash of its build context, never to its name — A bundle that reuses an image by name will carry a stale service for as long as the name stays the same; the kept image must be keyed to what it was built from, and the test that catches it is scoring the bundle-started estate against the answer key.
    49. 51 Where a protocol upgrade can be refused, ask for it once and record the answer before scanning what it would carry: a scanner that cannot represent a refusal records a timeout — A TLS scanner pointed at a PostgreSQL listener that refuses TLS waits out its budget and records a timeout, which reads as a failed scan; one SSLRequest answered N in a millisecond is the finding: the database speaks in the clear.
    50. 52 An inventory read as an ordinary user must list every path it could not open, and the plan must carry the privileged read as a step — Reading a server's files without privileges sees the public half of each key pair and none of the private keys; an inventory that drops the unreadable files silently looks complete and is not, so the reader lists them and the plan asks for one privileged, read-only pass.
    51. 53 An offline install carries the build backend with the wheelhouse and installs outside the lock file; nothing in the runbook calls the package manager's run command — A wheelhouse of runtime wheels is not enough: the project's own build needs its backend, a locked sync fetches from the lock's recorded URLs even with every wheel on disk, and a loader that shells out to uv run re-resolves the project on every call; install with uv pip --offline --no-index and run tooling under the environment's own interpreter.
    52. 54 When a box already serves the engines on its loopback, join their containers to the kit's bridge under the kit's names instead of starting them again — A harness that reaches its engines by container name on a bridge cannot see a port bound to the host's loopback; docker network connect --alias puts the box's own engine containers on the bridge under the names the tier map expects, with the box's tested launch recipe left untouched.
    53. 55 A reply cap on a thinking tier is a thinking budget: set it from the measured tokens of the role's hardest items, and record a cut-off as an empty reply — When a role is bound to an engine with reasoning on, the reasoning counts against the reply's token cap; a cap sized for the answer alone returns nothing on the items that need the most thought, and the only safe reading of a cut-off is a wrong reply.
    54. 56 A signer's first signature over an event is a floor on the span that starts there, never a reading of it; check a ledger's clock against the bracket, not the floor — An independent signer says when an event existed by (the first signature over it) and when it cannot have existed before (the last signature before it); a span measured from the first-seen time is a lower bound, and a ledger whose own span falls inside that bracket agrees with the signer.
    55. 57 When two renderers must show the same header, give them one stylesheet and one markup shape, copied at build time; a second implementation that matches by description drifts — A header that an application renders from a template and a static-site generator renders from a theme override stays identical only when both load the same stylesheet file and emit the same element shape; a second stylesheet written to look the same is a second design, and the reader sees the whole band change when they cross from one to the other.
    56. 58 A model whose chat template thinks by default must be told not to on every plain call, and its reply's shape belongs in the prompt and a validator, not in the engine's grammar — Nemotron's chat template reasons unless the request turns it off, so a short plain call spends its whole budget thinking and returns nothing; turn thinking off in the tier's request block, and with thinking off describe the JSON shape in the prompt and validate it, because the engine's structured-output grammar can run a call to its cap.
    57. 59 Serve a static site that is rebuilt in place with Cache-Control: no-cache; without it the browser keeps old pages for a tenth of their age — A response with Last-Modified and no Cache-Control lets the browser choose its own freshness, typically a tenth of the time since the file last changed, so a page built days ago is reused for hours after a rebuild; send no-cache, and the ETag keeps the check cheap.
    58. 60 Before a component goes in an architecture picture, find the line of code that calls it; a stack drawn from what the box has installed claims parts the system never uses — An architecture drawing is a claim about what the system does, so each box in it needs a call site, and each path through it needs a code path; drawing what is installed beside the system, or what a reference design would use, puts parts in front of an audience that a single question exposes.
    59. 61 Give an animated presentation a snapshot mode that draws each frame's final state at once, and photograph every frame before presenting it — Animated pages hide their defects in motion and in timing, and a headless browser photographs the first frame, not the last; a mode that skips delays and draws the end state lets a machine take a still of every beat, and the stills show text, overflow and errors that a run-through glides past.
    60. 62 Before a container changes the user it runs as, change the owner of the files it appends to in a shared, sticky directory; the kernel refuses even root — With fs.protected_regular set, as Ubuntu sets it, an open that may create a file in a world-writable sticky directory fails when the file belongs to someone other than the opener and the directory's owner, root included; a container switched from one uid to another over a kept volume cannot append to its own earlier log until the file is handed over.
    61. 63 A static copy of a page whose answer comes from a model shows a call made once and labelled, offers only the questions recorded, and runs the rule's check again where it is built — A published, static copy of the workbench has no model to call; its Ask the CBOM page shows the example questions answered once by a real call, labelled with the model, the hardware and the date, and recomputes every citation's verdict against the ledger it is published with, so the verdict a reader sees is never a stored one.
    62. 64 Run the accessibility check in every colour scheme a page ships; a palette that passes in light can fail in dark, and the reverse — WCAG contrast is computed from the colours a reader is shown, so a page with a dark and a light scheme is two pages to the checker; run it once per scheme.
    63. 65 Before making a shared directory's files private, list every process that reads them and the user each runs as — Before making a shared directory private, list every reader and the uid each runs as; where writers and readers differ, make the mode a setting.
    64. 66 Pinning a self-signed certificate by making it the only trust anchor still checks its dates; an expired management-controller certificate fails the pin — Loading the certificate a server served as the context's only trust anchor (with partial-chain verification for a leaf a CA issued) is a sound pin in Python's ssl module and anything built on OpenSSL, but OpenSSL still checks the anchor's validity dates, so a long-expired self-signed controller certificate is refused; renew it before turning the pin on, or the read stops before it starts.
    65. 67 Publish a running system as a recording, a record and notes; never as a static copy of its pages with the buttons disabled — A static copy of a live application's pages costs a fixture, a template branch and a dead-button note per page and grows with the application's features, not with its story; publish a recording, the documents it produced with their hashes, and screenshots in the notes instead.
    66. 68 When two sources describe one asset, keep every claim, put one in force by the grade of its evidence, and show the rest as dissent; never fold two values into a list — An inventory built from several tools gets two values for one field sooner or later; folding them into a list of both changes the field's type and tells the reader nothing, and taking the first silently loses the other. Keep each as a claim with its grade (watched on the wire, read from a host, parsed from a file, reported in a document), project the best-graded one, write the disagreement beside it, and let only a person's recorded resolution override the rule.
    67. 69 A policy pack written from secondary summaries is marked unverified and applies no date; the primary is read, hashed and quote-checked before any of its dates or names counts — Summaries of a standard describe the version their authors read; the standard moves on. A pack built from them carries verified: false, sets no deadline and marks every status provisional until the primary document is read first-hand, its hash recorded and every quote in the pack checked against its text by the loader; the CNSA 2.0 pack's five-category timeline, taken from two summaries that agreed, was not in the FAQ's current version at all.
    68. 70 A number shown on two pages is computed in one place; a page that counts a rule's events and a page that counts the document's entries will disagree — A rule judges each observation and the document folds several observations onto one entry, so a count of the rule's events and a count of the document's entries are two different numbers under one label; every page that shows the figure reads it from the same projection, and a test holds the two readers equal.
    69. 71 An automated keyboard pass counts only the controls that are shown; a control inside a closed disclosure is reached through its summary, and a page that takes focus on load is walked from where it starts — A Tab-order check that compares the controls it reached with every focusable element in the page reports traps that do not exist: links inside a closed details element are not in the tab order until it is opened, and a page that focuses its input on load starts part-way down. Count what is shown, follow the wrap-around, and explain every difference before reporting one.
    70. 72 A recorded model answer belongs to the scan it was asked about; a build that shows a newer scan stops until the answers are recorded again — A static copy has no model to call, so it shows what a model said once, recorded against one scan's record. When a newer scan becomes the one the copy shows, the recordings do not follow it, and the page publishes an empty answer unless the build refuses to run without them.
    71. 73 A demonstration written around one machine goes stale the day the machine leaves; name hardware once, as where a run was recorded, and build the beats on the approach — A stage whose beats name a box, its chips and its model on every screen is true for one day and one machine. Four days later its recording came from a different host with different models, and three machines were named across eight beats with no reconciliation. The fix is structural: the beats describe the approach, and hardware appears once, as the provenance label on the run the copy shows.
    72. 74 A drawing that must fit one screen takes its height from that screen, and shares it among its rows by what each row needs; a constant cap leaves room unused while the rows collide — The stage's opening drew three bands into a height capped by a stylesheet constant: on an 883 px screen it took 443 px, left 250 px empty under itself, and spread eight services 10 px apart in 12 px type. Sized from the screen and divided by what each band's rows need, the same drawing takes 600 px on that screen and nothing overlaps; four screen sizes were rendered to check.
