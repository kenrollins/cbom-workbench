    Lessons¶

    Standing guidance: the rule, why it holds, when it applies.

    • When verifying that a post-quantum key exchange is required, offer every classical group, not the ones the server was configured with — A refuse-probe built from the server's old configuration proves only that the old configuration is gone; build it from the whole class being retired, and let an enumerating scan overrule it.

    • Give an isolated Docker network no host address, and test for it — An internal Docker bridge has no route out, but the host still sits on it as the gateway; set the gateway mode to isolated, and probe for the host as well as for a route.

    • Carry a registry in an offline bundle; docker save and docker load do not preserve digest references — An image saved by digest loads back as an untagged id, and an image saved by tag loads back under a new digest; an air-gapped bundle that pins by digest needs a local registry, filled registry-to-registry with every platform.

    • Believe an identity header only on a connection from the proxy that sets it — A forward-auth proxy strips and sets the user header, but an upstream that listens where anything else can reach it will accept the same header typed by hand.

    • Score an inventory for what it invents, and put a decoy in every layer it is scored on — A coverage score with no penalty for unplanted claims is maximized by claiming everything; count claims the answer key does not hold as false positives, and never show an untested decoy as avoided.

    • Record which container a scan reached, and join evidence only when it is the one you think it is — An address is not an identity: before linking what was seen on the wire to what was found in an image, check that the container at that address runs that image, at the start and the end of the scan.

    • Take the key that verifies a signed log from somewhere other than the log — A public key stored beside the data it verifies can be replaced along with it; record the key's id and the latest signed checkpoint somewhere the writer cannot reach.

    • Identify a key in an inventory by the hash of its public key, not by where it was found — \"An RSA certificate at this address\" cannot tell a renewed certificate from the old one, and an image digest in the location makes every rebuild look like a new estate; put the public key's hash in the identity and keep build identifiers out of it.

    • Time a file scanner on the bare base image first; symlinks, not size, can set its cost — cbomkit-theia's secrets plugin reads a file's contents once for every symlink that points to it, so a BusyBox-based image costs it about 94 s whatever its size; measure the base before blaming the image.

    • Count a key-exchange group as accepted only when it is the one negotiated — and sweep TLS 1.2 groups as TLS 1.2 — A handshake can succeed on a group the client did not offer, and fail after the server has accepted the one it did; judge each probe by the group the server chose.

    • Prove a passive-monitoring script fires on traffic you generated before reading its silence as absence — Zeek ran a handler for an event that does not exist without a word and logged nothing; run every new detection against traffic known to contain the thing it detects.

    • Check cited evidence against the question it was meant to answer, then derive the conclusion again — That a cited test really ran proves nothing unless it is the test the claim calls for, run after the change, against the thing changed — and the conclusion follows from its raw output.

    • To bound when a logged event happened, sign the log just before it and just after — A timestamped signature over an event shows it existed by then; only an earlier signature that the event is chained after shows it did not exist before.

    • Do not switch branches under a running container that bind-mounts the tree; make the health check read the files — A bind mount follows the directory that existed when the container started; when a checkout deletes and recreates that directory, the container keeps an empty one and a liveness check still passes.

    • Hash every blob in an offline bundle's registry before serving it, and keep the checksum file's own hash somewhere else — A registry serves what is on disk without checking it, a client does not re-fetch what it holds, and a checksum file edited together with what it lists still passes.

    • Count a change as applied only when the service answers, and put the old configuration back when it does not — The orchestrator reporting a container started is not the service coming up; a configuration the service cannot load leaves it down unless the applier restores the previous one.

    • In a bundle build, always rebuild what must match the source and record the commit; reuse only what must not change — A build step that skips an image because its tag already exists ships whatever was built first; a test of the bundle then tests old code.

    • Observe what a service accepts with nothing configured before planning its migration — The same TLS library gives different key-exchange defaults under different servers; with no line set, one already offers the hybrid group and another does not, and both accept RSA key transport.

    • Label a cause only after changing it and watching the effect go — A reference answer of the form 'this line causes that behaviour' is earned by two observations: the behaviour with the line as written, and its absence with the line changed.

    • Before reading a configuration, know which occurrence of a setting wins in that software — OpenSSH takes the first value it reads, PostgreSQL the last, nginx the innermost block; the same two lines in a different order, or an include in a different place, give a different listener.

    • Set a floor per role before comparing two models, and repeat every call before believing it — A model that beats the smaller one is not thereby good enough: each role needs an absolute bar set by what depends on its output, and a reply at temperature 0 is one draw, not an answer.

    • Deploy from a checkout nobody edits — A running container that bind-mounts a directory from a development tree breaks silently when a branch switch replaces that directory; run a deployment from its own detached checkout, with its state beside it, and move it to a commit on purpose.

    • A hardware label in a config is a claim; record what served the call — When model calls go through a gateway that can move a lane between machines, the hardware label in the caller's config is a claim that goes stale silently; record the upstream the gateway names on each reply beside the label, and check the label against it before publishing a timing.

    • Size the scanner network's address range to the parallelism, and record a job that never started as its own failure — When scanners run as containers on a network with a fixed address range, the range bounds how many can run at once; a job that fails because no address was free must be recorded as a runner failure with its reason, never as a scan the target did not answer.

    • Name the reasoning setting beside the model in every measurement and binding — A hybrid-reasoning model's result depends on its reasoning switch and effort level as much as on its weights, so a measurement, a table row or a tier binding that names the model without its reasoning setting is incomplete, and a gateway lane that pins the setting is part of the model's name.

    • Before keying a TLS listener, probe each kind of key exchange on its own: named groups, finite-field DHE, RSA key transport — A TLS 1.2 listener can establish keys three ways — a named group, an ephemeral finite-field group it supplies itself, or encryption to its RSA key — and a probe that offers one kind says nothing about the other two; key a listener only after a probe per kind, or a full cipher-suite enumeration.

    • Read a certificate's CA flag together with its key usage; a self-signed server certificate is usually marked CA:TRUE — openssl req -x509 writes basicConstraints CA:TRUE into every self-signed certificate it makes, server certificates included, so an inventory rule that treats CA:TRUE as 'a certificate authority' misfiles them; a certificate authority's certificate is one with CA:TRUE and keyUsage keyCertSign, and the in-use rules for leaf certificates must not be applied to it.

    • Give a listener that carries TLS behind a protocol upgrade its own scan profile; a plain TLS scan of its port is silent, not negative — PostgreSQL, SMTP, IMAP, LDAP and others start TLS only after an in-protocol request, so a scanner that opens the port and speaks TLS gets nothing back and reports nothing; the listener's protocol must be named in the scope and bound to a profile that speaks the upgrade, and a scope protocol no profile claims must be visible as unscanned, never as clean.

    • Confirm every cause an answer key names by changing it, including the ones written as annotations — A cause written into an answer key as an aside — a trace, a hint, a why — is a label like any other and needs the same two observations; one the key's author wrote from reading named a commented-out line as the cause of a default, and the first model trace to reach it was right where the key was wrong.

    • Ask the protocol stack's runtime what it will negotiate before calling a migration blocked, or not blocked, by its supplier — Whether software can offer a post-quantum algorithm is a property of the protocol stack that negotiates it, not of the cryptographic library underneath; ask that runtime for its own list, with no network, and keep the raw answer.

    • Read a validated module's certificate for the algorithm you need, and check that the module is active, before calling a system validated — A FIPS 140 validation covers the algorithms its certificate lists, in the module it names, when that module is the one in use; the library's name and version say none of that, and a FIPS provider shipped in an image is not one in use.

    • Score the retrieval step on its own before scoring a model's answer over it — When a model answers from retrieved passages, record what was retrieved with every answer and score whether the passage that settles the question was among it; a faithful model fails every item retrieval misses, and the failure is not the model's.

    • Compare two inventories by the identity of each observation and by what it says, leaving out references to the records behind it — A component's reference should be a hash of what was observed, so the same thing seen twice is the same entry; and a comparison should strip the event ids an entry cites, which are new on every scan, or every scan of an unchanged estate looks like change.

    • When verifying that a listener requires post-quantum key establishment, probe TLS 1.2 on its own; a classical-only TLS 1.3 client is refused, not downgraded — A server that shares no group with a TLS 1.3 client refuses it rather than falling back to TLS 1.2, so a negative probe offering every classical group says nothing about TLS 1.2; a listener restricted to the hybrid group can pass it while still accepting finite-field Diffie-Hellman and RSA key transport over TLS 1.2.

    • When a probe claims a handshake the enumerating witness does not find, call the verdict inconclusive and say why; neither side settles it — A verifier that lets its witness only lower a verdict will silently turn a misread probe into a false 'not enforced'; when the negative probe reports a key exchange the witness says the listener does not offer, one of the two misread the listener, and the verdict is inconclusive with the reason, until a person reads the raw output.

    • Before citing or redrawing a standard, read its status on the publisher's page; cite the current revision by its own identifier — A withdrawn publication keeps circulating — in search results, in summaries, in copies saved earlier — so the identifier in hand may not be the one in force; read the status, cite the superseding revision, and say whether the part relied on changed.

    • Every label in a diagram of what a system does is a claim; fill it from the record and check each against the record before it is shown — A box that says 'signed', 'by rule' or 'reached' reads as fact, and a framework's boxes invite filling them with what the system ought to do; compute each label from the ledger where it can be computed, and check the rest line by line against the ledger before the page is published.

    • Draw a cryptographic inventory in columns along its dependency chain, not as a force-directed graph — A CBOM already has an order — service, listener or image, asset, file — so draw each link of that chain as a column, one service's chain at a time, and group bulk files by directory; a force layout throws that order away and, unbounded, drifts nodes off the canvas.

    • Before approving a change that requires post-quantum key establishment, probe each kind of client against a copy with the change; enforced says it landed, not whom it refuses — A require change verified enforced has, by definition, refused every client that cannot offer the hybrid group; measure which kinds those are, against the live listener and a copy with the proposed configuration, and put that table in front of the approver.

    • Before trusting a discovery tool's silence, show it something it should find; an empty result is a finding about the tool until then — A scanner that reports nothing has either found nothing or cannot see — a hybrid group its TLS library lacks, a library it has no rules for, code it cannot resolve without a build — and only a known positive tells the two apart.

    • Report a change's time from approval to proof beside its time from policy to proof; the gap is the wait for a person, not the system — Time from the policy decision to the last verdict includes however long the change waited for an approver; shown alone it reads as the system's speed, so headline the approval-to-proof time and give the other as what it is.

    • Publish a curated export, checked for leaks, not the working repository; and keep the list of what must not leak out of the published tools — A working repository built in a real environment carries that environment in its history, its tests and its notes; publish a fresh tree exported from it, with private passages marked at the source and stripped on export, a scan that refuses the export on any match, and the scan's own patterns kept private.

    • Score an inventory against a key that knows about changes: an item a verified change removed is remediated, not missed — When the estate an answer key describes can be changed, a scan after a verified change no longer sees what the change removed; count each such item as remediated, by the change event that removed it, and take it out of the denominator, or every successful migration reads as a drop in coverage.

    • After publishing a repository, read its own checks: they run in an environment the export was never tested in — A repository published from a private working copy carries workflow files written for some earlier state of it; they run on every public push, and a red mark on the front page is the first thing a reader sees. Run the workflows' steps on a clean copy of the export before publishing, and read their result after.
